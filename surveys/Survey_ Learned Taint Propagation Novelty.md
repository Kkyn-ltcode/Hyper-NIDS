# **Neural Information Flow and Learned Taint Propagation in Cybersecurity: A Comprehensive Analysis of State Space Models and Provenance Graph Intrusion Detection**

## **Introduction**

Information flow tracking and taint analysis have long served as the foundational pillars in the domain of cybersecurity, utilized extensively for vulnerability detection, data provenance, malware analysis, and intrusion detection. Historically, the methodologies driving these critical security analyses have relied upon deterministic, rule-based propagation engines designed by human operators. However, the escalating complexity of modern software ecosystems, the proliferation of stealthy Advanced Persistent Threats (APTs), and the sheer, unbounded volume of system audit logs generated by distributed networks have exposed the scalability and accuracy limits of traditional paradigms. The convergence of machine learning with program analysis has catalyzed a paradigm shift across the industry, transitioning rigid, statically defined tracking rules into dynamic, learnable representations capable of generalizing across novel attack vectors.  
The concept of "neural information flow" originally emerged in the field of neuroscience to describe the complex movement of activity between neurons and diverse brain areas. In this biological context, neural information flow is typically analyzed through sophisticated statistical models, such as continuous-time weighted dynamic Bayesian networks and multivariate Granger causality, to capture time-varying dynamics and smoothly time-varying conditional dependencies within the cortex.1 In recent years, this biological nomenclature has been co-opted and adapted by the computational systems security community. In the realm of computer science, "neural information flow" has come to describe the flow of tainted data through neural network approximations of program execution, transforming how information leakage and execution influence are tracked.4  
Concurrently, macro-level system security has increasingly adopted data provenance graphs—structured, directed acyclic graphs derived from operating system audit logs that describe the precise causal history of system execution—to detect and investigate stealthy APTs.6 Despite the integration of Graph Neural Networks (GNNs) and advanced sequential models to analyze these provenance graphs, a critical architectural gap remains.  
This report provides an exhaustive, deeply technical investigation into the intersection of learned taint propagation, graph representation learning, and the nascent application of State Space Models (SSMs), such as the Mamba architecture, in cybersecurity. The primary objective is to evaluate the technical landscape to determine the novelty of proposing a learnable state propagation mechanism—driven specifically by SSMs—across interconnected entities within a system provenance graph. By dissecting static and dynamic taint analysis, neural information flow tracking, decentralized information flow control (DIFC), and state-of-the-art APT detection frameworks, this analysis isolates the precise boundaries of unchartered research territory. The central hypothesis is that while neural networks have been used to learn taint rules for binary fuzzing, and SSMs have been used for anomaly detection on provenance graphs, no existing system utilizes an SSM to execute an end-to-end learnable state propagation rule across a provenance graph for intrusion detection.

## **The Theoretical Foundations of Information Flow and Taint Analysis**

To fully contextualize the theoretical leap required to achieve learned state propagation, it is imperative to rigorously trace the evolutionary trajectory of traditional taint analysis. Taint tracking fundamentally involves identifying sensitive, privileged, or untrusted data (defined as sources) and deterministically monitoring its flow through program execution to critical, vulnerable execution points (defined as sinks).8

### **The Mechanics of Static Taint Analysis**

Static taint tracking examines all feasible program paths without actually executing the underlying code. It is formally articulated as a data flow analysis problem computed over abstract mathematical representations of the program, most commonly Control Flow Graphs (CFGs), Interprocedural Control Flow Graphs (ICFGs), or highly specialized Value Flow Graphs (VFGs).8 Static approaches attempt to map all possible propagation routes prior to runtime, making them highly comprehensive. This class of analysis underpins a wide variety of security tools for privacy auditing, web vulnerability detection, and compliance.8  
However, static analysis is inherently plagued by precision issues. Because it operates globally and strives to capture all flows, including those passing through complex control dependencies (code branches contingent on tainted values) and sophisticated program features like pointers and heap objects, it frequently results in over-approximation.8 To track taint through object fields and arrays, systems often utilize access-path abstractions, representing nested field accesses (e.g., ![][image1]) bounded by k-limiting strategies to ensure computational scalability.8 Furthermore, mobile and web frameworks present unique structural challenges that break CFG continuity. For instance, Android's component-based architecture requires tools like IccTA to transform code and connect components artificially, thereby preserving taint context across Inter-Component Communications (ICCs).8 Despite these advanced abstractions and hybrid techniques—such as integrating static binary control flow analysis with mutation-based dynamic analysis via frameworks like ![][image2]Dep—static taint tracking inevitably suffers from high false-positive rates and specification drift.8

### **The Dynamics and Limitations of Runtime Taint Tracking**

Dynamic Taint Analysis (DTA), conversely, tracks information flow during the actual runtime of a program. It utilizes dynamic binary instrumentation (DBI) or dynamic binary translation to monitor data as it is actively read from and written to physical or virtual memory locations, applying taint tags to variables and propagating them through move, arithmetic, and control operations at the processor instruction level.11 A typical dynamic propagation rule operates strictly on deterministic boolean logic. For example, in a binary arithmetic operation ![][image3], assuming ![][image4] and ![][image5] represent the boolean taint status of the operands, the taint tracking rule dictates that the output variable is tainted if either input is tainted: ![][image6].12  
While DTA provides exact, concrete runtime context—eliminating the over-approximation of dead code paths seen in static analysis—it suffers from severe operational limitations.  
First, the performance overhead of monitoring every dynamic binary instruction is notoriously prohibitive. The continuous maintenance of taint maps and the interception of CPU registers impose massive latency penalties on target applications.13 While researchers have explored hardware virtualization systems and memory management exception handlers to offload taint status propagation, and have even successfully ported taint tracking to GPUs to leverage parallel processing, overhead remains a persistent bottleneck.12 On GPUs, optimizing tracking by filtering un-taintable runtime parameters and maintaining hot portions of the taint map in large register files can improve performance by 5 to 20 times, yet this still requires immense computational dedication.12  
Second, DTA is crippled by rule inflexibility and sequential error accumulation. DTA relies entirely on hardcoded, instruction-by-instruction rules crafted by human engineers. It struggles immensely to accurately capture implicit control flows—where data is not directly moved, but its value influences the control path of the program, thereby leaking information.5 Attempting to track implicit flows with rigid rules typically triggers massive false positive rates (overtaint). Conversely, failing to track them results in missed vulnerabilities (undertaint).5 When these overtaint and undertaint errors accumulate sequentially across millions of dynamically executed operations, the final taint status at the sink becomes fundamentally unreliable.5

## **The Transition to Machine Learning in Taint Analysis**

The recognition that manual specification of taint rules is incomplete, error-prone, and mathematically brittle led the research community to explore machine learning. However, the integration of statistical models occurred in distinct phases, initially acting merely as a filtering mechanism before evolving into genuine neural state propagation.

### **Probabilistic Filtering and Specification Inference**

The initial integration of machine learning into taint analysis aimed to filter the output of deterministic engines, effectively addressing the problem of "unexpected" taint flows. In complex codebases, simply proving that a flow exists from a source to a sink is insufficient; one must determine if the flow violates intended security policies.9 For example, learning that an API parameter named locale ends up executing in a file path is highly suspicious, whereas a parameter named command passed to an execaCommand API is completely expected behavior.15  
This nuance is captured by the "Fluffy" framework, a bimodal taint analysis system that combines standard static data flow analysis with machine learning models that process natural language artifacts within the code.9 Fluffy first runs an off-the-shelf, monomodal static taint analysis that massively overapproximates potential flows.9 The resulting candidate flows are then filtered by a machine learning model—which can range from Support Vector Machines (SVMs) to Large Language Models (LLMs) like Codex—that probabilistically predicts whether the flow is semantically problematic based on API names, documentation, and variable identifiers.9 Fluffy achieves impressive F1 scores exceeding 0.85 across datasets comprising 250,000 JavaScript projects.9 However, while Fluffy utilizes neural models to augment specification inference and filter the final results, the underlying state propagation mechanism moving the taint from source to sink remains firmly rooted in classical, deterministic static CFG traversal.9

### **Genuine Neural Taint Propagation: Making the Rules Learnable**

The actual substitution of rule-based, instruction-level propagation with learnable neural representations was pioneered by frameworks such as Neutaint and nnTaint. These systems mark a profound conceptual leap, translating the concept of "neural information flow" from biological systems into a rigorous mathematical framework for software security execution traces.  
Neutaint completely abandons discrete, boolean instruction-level rules.5 Instead, it employs neural program embeddings to holistically model the computations taking place between taint sources and sinks within a target program.5 By observing a diverse set of execution traces—collected through highly lightweight, semantic-level instrumentation rather than heavy instruction-level tracking—Neutaint trains a neural network to approximate a continuous mapping function from specific inputs to specific outputs.5  
The elegance of Neutaint lies in its mathematical architecture. Because neural networks approximate continuous mathematical functions, they are differentiable. Neutaint leverages this by utilizing automatic gradient computation and the calculus chain rule to track the end-to-end mathematical influence of sources over sinks.5 Instead of writing a rule that says ![][image6], Neutaint calculates the exact first-order partial derivative of the sink variable with respect to the input source bytes.5 This mechanism intrinsically solves the overtaint and undertaint accumulation problem, as the model learns the exact mathematical sensitivity of the program's paths.5 Neutaint utilizes these gradients to construct both coarse-grained saliency maps (summarizing information flow across all taken paths) and fine-grained saliency maps (analyzing detailed influence for precise source-sink pairs).5 This learned propagation achieves a 40-fold runtime overhead reduction compared to traditional tools like Libdft and drives a 61% increase in edge coverage during taint-guided fuzzing, proving that neural attribution is vastly superior to boolean logic for tracking dynamic information flow.5  
Similarly, the nnTaint framework addresses the high false-positive rates associated with implicit control flows by utilizing Long Short-Term Memory (LSTM) recurrent neural networks.14 nnTaint collects variant corpora from fuzzers, extracts comparison instruction operands dynamically, and trains an LSTM to learn the temporal relationships and variable-length sequence dependencies between raw input bytes and target conditional branches.17 Because traditional fully connected neural networks cannot handle variable-length input sequences, the LSTM architecture is critical for learning the timing features of dynamic program execution.17 This model effectively builds a predictive mapping function that dictates taint propagation logic, improving operation efficiency by up to 18.8% over traditional taint analysis and enhancing edge coverage on benchmarks like the LAVA-M datasets and GNU binutils.14

While both Neutaint and nnTaint successfully demonstrate that state propagation rules can be learned directly from execution data, their architectural scope is strictly constrained. They are confined to analyzing singular program executions (binary-level analysis) for the purpose of fuzzing. They map input bytes to memory addresses or specific branch instructions. Crucially, they do not extend their learnable propagation mechanics across distributed system entities, nor do they operate on macro-level system provenance graphs representing complex, multi-process interactions.

## **Data Provenance and Graph-Based Intrusion Detection**

To achieve system-wide intrusion detection, advanced threat hunting, and decentralized information flow control, security architectures rely on data provenance rather than binary execution traces. Provenance graphs are structured audit logs formulated as Directed Acyclic Graphs (DAGs).7 Within these graphs, nodes represent distinct system entities (e.g., processes, files, network sockets, memory objects), while edges represent the causal interactions and information flows between them (e.g., a process writing to a file, or a process opening a network connection).18

### **The Role of Provenance in APT Detection**

Data provenance provides the historical and contextual breadth necessary to detect Advanced Persistent Threats (APTs). APTs are defined by their "low-and-slow" attack patterns, where highly resourced adversaries navigate across application boundaries over extended periods, often mimicking benign system administration activities to evade deep packet inspection, signature-based antivirus systems, and static anomaly detectors.6  
Because provenance graphs preserve the precise causal chain of events, they inherently track the flow of information across the system, acting as a macro-level, system-wide taint tracker. If a malicious payload is downloaded via a network socket, written to a temporary file, and later executed as a child process, the provenance graph structurally connects these causally related events, regardless of the time elapsed between them or the specific application boundaries crossed.7

### **The Dependency Explosion Problem**

However, analyzing system provenance is computationally grueling. Operating systems generate an unrelenting stream of audit logs, causing the provenance graph to grow continuously. When attempting to reconstruct an attack path or trace the origin of a suspicious event, analysts encounter the "dependency explosion" problem.21 Because modern operating systems utilize highly interconnected shared resources (e.g., core system libraries, common configuration files, shared memory segments), a single tainted entity can rapidly create an exponential spread of causal edges across the graph.21  
Traditional provenance tracking systems attempt to mitigate dependency explosion using arbitrary, rule-based heuristics such as "tag attenuation" or "tag decay," where the assigned threat level of an event decays over time or distance from the source.21 These rules are inherently brittle, requiring constant manual tuning by experts and remaining vulnerable to evasion by adversaries who simply slow their attack cadence to wait out the decay timers.

### **Graph Neural Networks (GNNs) in Provenance Analysis**

To automate threat detection and bypass the limitations of rule-based dependency heuristics, researchers have increasingly adopted graph representation learning. Several prominent frameworks utilize Graph Neural Networks (GNNs) and graph sketching techniques to automate APT detection:

1. **Unicorn:** This system bypasses the need for an in-memory representation of massive, continuous provenance graphs by utilizing an innovative graph sketching technique.7 It builds an incrementally updatable, fixed-size longitudinal graph data structure that allows for space-efficient exploration of provenance history from system boot to shutdown.7 Unicorn models the evolving behavior of the system, employing a graph similarity matching method and clustering to identify anomalous graph states without relying on predefined attack signatures.7  
2. **KAIROS:** Identifying the limitations of broad graph similarity matching, KAIROS introduces a fine-grained, temporal-spatial GNN encoder-decoder architecture that explicitly learns the temporal evolution of a provenance graph's structural changes.6 It quantifies the degree of anomalousness for individual edges based on how much the historical behavioral patterns of their corresponding nodes deviate from known benign executions.18 KAIROS effectively correlates these anomalous edges based on information flow to reconstruct highly compact summary graphs that accurately describe malicious activity over a stream of audit logs.18  
3. **Flash:** To facilitate real-time APT detection without the prohibitive latency of continuously regenerating node embeddings, Flash introduces a two-step process.22 It generates semantic embeddings using Word2Vec and contextual embeddings via GNNs (specifically utilizing Sage Convolutions, which aggregate neighboring node features).22 Flash then operates a lightweight real-time XGBoost classifier against an embedding recycling database to detect anomalies efficiently.22  
4. **TPPR:** Taking a slightly different approach, the TPPR framework integrates explicit Attack Tactic/Technique (TTP) pattern matching (derived from the MITRE ATT\&CK framework) with anomaly subgraph extraction.23 It reduces the complexity of direct reasoning by pruning the provenance graph down to only suspicious semantics, subsequently utilizing heuristic graph walking and confidence-based path scoring to infer sophisticated APT attack paths.23

While these GNN-based systems are exceptionally sophisticated and represent the current state-of-the-art in intrusion detection, their approach to analyzing information flow remains implicit. They learn the *structural anomaly* of the graph topology or the *embedding representation* of the nodes, but they do not explicitly frame the problem as "learned state propagation" or "learnable taint." In these systems, the flow of information is statically represented by the existence of the edges in the DAG, and the neural network evaluates the topological normalcy of that structure. They do not maintain a dynamic, continuous state vector that actively calculates how influence transfers from one node to the next based on a learned propagation rule.

## **State Space Models (SSMs) in Sequential Security Analysis**

The introduction of structured State Space Models (SSMs) into the deep learning ecosystem, particularly the Mamba and Mamba-2 architectures, represents a critical inflection point in sequence modeling. For years, Transformers have dominated representation learning in natural language processing and sequential analysis. However, the quadratic computational complexity of the self-attention mechanism renders Transformers highly inefficient for the ultra-long contexts required in continuous system audit logs and network traffic analysis.19

### **The Architecture of Selective State Spaces**

Mamba resolves the context bottleneck of Transformers by utilizing an input-dependent selection mechanism combined with hardware-friendly fused kernels.19 The lineage of these models traces from HiPPO through structured state spaces (S4, S4D, DSS, S5) to selective dynamics.25  
In a standard structured SSM, the state transition parameters (often denoted as ![][image7] and ![][image8]) define how the continuous hidden state evolves over time. These parameters are typically time-invariant, meaning the model applies the same linear transition dynamics regardless of the input data. Mamba fundamentally alters this architecture by making the state transition parameters functions of the current input.25 This allows the model to selectively filter information—memorizing relevant context while discarding irrelevant noise—dynamically adjusting its state based on what it is reading.25 This architecture achieves linear-time complexity and high throughput, making it exceptionally well-suited for processing unbounded streams of security events.19

### **SSMs in Traffic Analysis and Intrusion Detection**

The security community has rapidly begun integrating Mamba into anomaly detection workflows, recognizing its superiority for long-context sequential data.  
For instance, the MeeDet framework utilizes a 12-layer unidirectional Mamba backbone to detect malicious traffic in Industrial Internet of Things (IIoT) scenarios.19 IIoT environments rely heavily on stateful, command-driven industrial control protocols (e.g., Modbus, DNP3) characterized by highly regular inter-arrival times and strict real-time constraints.19 MeeDet tokenizes raw network packet captures into standardized, stride-based sequences, leveraging Mamba's long-range temporal coherence to identify low-and-slow IIoT attacks that perfectly mimic benign behavior and evade short-context attention models.19 Furthermore, MeeDet incorporates dynamic early-exit mechanisms by attaching lightweight binary classification heads to individual Mamba layers, terminating inference early for high-confidence benign flows to drastically reduce computational latency on resource-constrained edge gateways.19  
While MeeDet clearly demonstrates Mamba's efficacy in network security, it treats packet sequences as isolated, linear streams rather than interconnected, multi-dimensional graphs of system provenance.

### **The Attack Surface of State Space Models**

If an SSM is to be utilized as the core engine for security analysis—and potentially for state propagation—it is critical to acknowledge the attack surface of the model itself. Deep SSMs operating on long sequences exhibit unique vulnerabilities that are structurally absent from attention-based models.25 Because SSMs must mathematically compress and continuously discard information to maintain their linear hidden state, they present novel attack vectors for adversaries:

1. **State Erasure and Saturation:** Attackers can craft inputs specifically designed to oversaturate the hidden state dimensions, forcing the model to confidently produce outputs based on corrupted or compressed state, or forcing it to forget critical prior context necessary for intrusion detection.25  
2. **Selection Subversion:** In Mamba-class models, the input-dependent projection computes the gating mechanisms. Adversarial inputs can manipulate these projections to adversarially open or close the state gate, effectively blinding the model to specific sequence anomalies or evading detection.25  
3. **Spectral Input Exploitation:** The convolutional view of SSM layers reveals that they act as learned filters over specific frequency bands. Attackers can exploit filter sensitivity in privileged frequency bands to inject adversarial perturbations.25

Governance-aligned mitigations, such as continuous state entropy monitoring, spectral input filtering, and ensuring strict tokenization boundaries on audit log fields, are absolutely required to ensure the integrity of the SSM when deployed in safety-critical audit log processing.25

## **The Closest Antecedent: The Sentient Framework**

When evaluating the novelty of combining SSM-based state propagation with provenance graphs, the closest existing research antecedent is the **Sentient** APT detection framework.20 An exhaustive analysis of Sentient is critical to delineating the exact boundaries of current research.  
Sentient identifies that while traditional GNNs are powerful, they suffer from a limited receptive field, often missing critical indirect dependencies in highly complex, obfuscated attack scenarios.20 Furthermore, existing methods struggle with the noisy, complex scenarios inherent in enterprise provenance graphs, often lacking the ability to associate logical behavioral relationships between seemingly disparate events.20  
To counter this, Sentient employs an innovative dual-architecture approach, merging graph topology with selective state space sequence modeling:

1. **Graph Comprehension (Graph Transformer):** Instead of relying on standard localized GNN convolutions, Sentient utilizes a Graph Transformer enriched with semantic and positional encodings.20 This allows the model to attend to all pertinent node information across the entire provenance graph, rather than merely aggregating localized neighborhood information, effectively capturing hidden, indirect dependencies.20  
2. **Intent Analysis Module (Bi-Mamba2):** This is where Sentient integrates state space modeling. Sentient extracts "multi-scenario behavioral sequences" from the provenance graph, which are essentially long sequences of node IDs representing specific chains of interactions (e.g., a process forking, executing, reading a file, and exiting).29 Sentient maps these sequences to node embeddings (generated during the Graph Comprehension phase) and feeds them into a Bidirectional Mamba-2 (Bi-Mamba2) model.29 The Bi-Mamba2 model leverages both forward and backward contextual information to learn the "behavioral intentions" and logical associations of events within the scenario sequence.30 Finally, Sentient employs a Multi-Layer Perceptron (MLP) to predict the probability distribution of benign interaction types (e.g., read, write, execute) between a source node and a destination node.29 Malicious activities are detected when the observed actual behavior heavily deviates from the benign intent distribution predicted by the Bi-Mamba2 model.20

Sentient achieves state-of-the-art results, boasting 96% accuracy, 99% recall, and an average false positive rate reduction of 44% compared to legacy systems.20  
**Crucial Distinction:** Sentient represents a monumental step forward by combining global graph structural learning with Mamba-based sequential modeling. However, a deep structural analysis reveals that Sentient is fundamentally an *intent prediction and anomaly detection* engine. It uses the Bi-Mamba2 model to classify the sequential context of a historical path extracted from a graph. It does *not* utilize the Mamba architecture to execute a continuous, dynamically learned state propagation rule. In other words, Sentient does not track an explicit, moving "taint" state as it transfers from Node A to Node B. The output of Sentient is an anomaly score or a probability of intent deviation, not a computed propagation state.

## **Decentralized Information Flow Control and LLM Memory Lineage**

To further establish the context of state propagation, it is necessary to examine how information lineage and flow control are managed in distributed agent architectures and modern Artificial Intelligence (AI) systems.

### **Event-Driven Systems and State Isolation**

In modern autonomous, agentic event-driven architectures, system state is typically materialized and shared through continuous, highly resilient data streams (e.g., Apache Kafka or Apache Flink) rather than being hidden inside monolithic services.31 A core, non-negotiable tenet of these architectures is state isolation: independent AI agents read from a shared, continuously updated state layer but never mutate state directly; all updates must flow through discrete, observable events.31 This architectural constraint ensures that decisions remain auditable, replayable, and subject to strict governance.31  
Decentralized Information Flow Control (DIFC) in such multi-agent systems relies heavily on tracking the provenance of these events to ensure sensitive or unauthorized data does not cross privilege boundaries. Currently, this tracking is almost entirely deterministic and policy-driven, relying on strict schema governance, explicit access controls, and hardcoded correlation logic rather than dynamically learned neural flow representations.31 The need for a system that can *learn* how state propagates through a stream of microservices, rather than relying on manually defined schema rules, is highly apparent but currently unfulfilled.

### **LLM Agent Memory Lineage (MemLineage)**

The challenge of information flow tracking has most recently extended to Large Language Model (LLM) agents. In persistent agent ecosystems, untrusted data (e.g., ingested via indirect prompt injection from a malicious webpage) can be written into the agent's persistent memory state.32 During future sessions, this poisoned state can re-enter the context window as an instruction, justifying unauthorized sensitive actions (like unauthorized banking transfers).32  
The **MemLineage** framework addresses this explicit state tracking problem by treating memory poisoning as a chain-of-custody issue.32 MemLineage attaches both cryptographic provenance (anchoring per-principal Ed25519-signed entries in an RFC-6962 Merkle log) and LLM-mediated derivation lineage to every memory entry.32 To track this flow, MemLineage constructs a Directed Acyclic Graph (DAG) over the memory store, where edges represent the derivation influence of past retrieved memories on the generation of new memories.33  
Crucially, to enforce security, MemLineage utilizes an explicit propagation rule known as **max-of-strong-edges**.33 This rule dictates that if any path from an external, untrusted ancestor maintains strong attribution weights across all edges in the DAG, the resulting chain tip inherits the "untrusted" label, prompting a sensitive-action policy gate to refuse execution.33  
While MemLineage incorporates sophisticated attribution algorithms (including LLM self-evaluation judges and white-box attention sweeps over inference models like Qwen2.5) to determine the *weight* of an individual derivation edge, the actual state propagation mechanism itself (the max-of-strong-edges logic) is entirely deterministic and rule-based.33 It enforces an Untrusted-Path Persistence theorem.33 MemLineage is, essentially, the conceptual equivalent of traditional dynamic taint analysis, adapted for the semantic memory graphs of LLMs. It proves the absolute necessity of tracking state across DAGs, but it does not make the propagation rule itself learnable.

## **Synthesizing the Novel Paradigm: Learnable SSM-Based State Propagation**

Having established the exhaustive state-of-the-art across deterministic taint analysis, neural program embeddings, GNN-based provenance detection, SSM sequential modeling, and agent lineage tracking, the core proposition can be definitively evaluated: **Utilizing an SSM-based mechanism to enable end-to-end learnable state (taint) propagation across entities within a system provenance graph for security purposes.**

### **Gap Analysis: Defining the Boundaries of Novelty**

To definitively claim novelty, the proposed architecture must be clearly differentiated from the most closely related works in the literature—specifically Neutaint, KAIROS, and Sentient.

1. **Differentiation from Neutaint and nnTaint:** Neutaint and nnTaint successfully demonstrate that taint propagation rules can be learned via continuous neural mapping rather than hardcoded boolean logic.5 However, the critical gap is their scope and scale. These systems are strictly confined to analyzing binary-level execution traces within a single program's memory space to assist fuzzing tools. They map input bytes to memory addresses or conditional branches. They do not scale to operating system-level distributed events, nor do they operate on graphical topologies. A mechanism that brings this "learnable propagation" concept to the macro-level of processes, files, and sockets is unprecedented.  
2. **Differentiation from KAIROS, Flash, and TPPR:** KAIROS and Flash apply sophisticated Graph Neural Networks to system provenance graphs to identify spatial-temporal structural anomalies and reconstruct attack footprints.18 The gap here lies in the mechanism of detection. These systems infer maliciousness from the overall structural deviation of the graph's topology. They do not explicitly model the *flow of a specific state* (like a taint tag) moving from node to node. The information flow is an implicit byproduct of the graph's existence, not a dynamically calculated, explicitly propagated state vector.  
3. **Differentiation from Sentient:** Sentient represents the absolute frontier, utilizing a Graph Transformer for structural dependencies and a Bi-Mamba2 model for sequence analysis over provenance paths.28 The gap lies in how the SSM is utilized. Sentient uses Mamba to classify the benign or malicious nature (intent) of a sequence of historical behaviors.29 It is fundamentally an anomaly detector operating on extracted paths. It does not use the SSM to calculate *how state transfers* between entities. In a true state propagation model, the SSM would ingest Node A's current state vector alongside the Edge attributes (the system event) to dynamically compute and output the resultant state vector of Node B. Sentient predicts intent; it does not propagate state.

### **The Mechanics of the Proposed Contribution**

Based on this exhaustive review, the proposed core idea—using an SSM to execute learnable state propagation across entities in a provenance graph—is genuinely novel and represents a distinct architectural contribution to the field of systems security.  
No existing paper from the programming languages, systems security, or machine learning communities has combined these specific elements in this precise functional configuration. The innovation lies entirely in redefining the operational purpose of the State Space Model. Rather than using the SSM simply as a sequential anomaly classifier (as seen in MeeDet and Sentient), the proposed idea utilizes the SSM's hidden state dynamics as the literal vehicle for "taint."  
In this novel architectural paradigm:

* The system provenance graph provides the topological map of interactions.  
* The system audit events (e.g., process forks, file reads, socket writes) act as the input tokens sequence.  
* The SSM does not simply flag an anomaly score. Instead, it actively calculates the likelihood of malicious influence transferring from a source entity to a destination entity.  
* The propagation rules are entirely data-driven. Instead of a security engineer writing a brittle, deterministic rule stating that "a process reading a tainted file immediately becomes tainted," the SSM learns the latent, non-linear correlations of influence transfer from historical attack data and benign baselines, effectively deciding on a case-by-case basis how much "state" to transfer across an edge.

This approach elegantly bridges the micro-level mathematical precision of neural taint tracking (seen in Neutaint) with the macro-level systemic visibility of provenance-based intrusion detection (seen in KAIROS and Sentient).

## **Strategic Implications and Conclusion**

The synthesis of State Space Models, learnable taint propagation, and data provenance graphs yields several critical insights and actionable technical conclusions for future architectural development in intrusion detection and information flow control.

### **Overcoming the Brittleness of Provenance Dependency Explosion**

Current provenance-based Intrusion Detection Systems (IDSes) are inherently limited by dependency explosion, necessitating arbitrary, human-engineered tag decay rules to prevent false-positive cascades across shared system resources.21 A learned state propagation mechanism natively solves this systemic flaw. By utilizing the Mamba architecture, the model's data-dependent selective state gating allows it to autonomously learn contextual attenuation. The SSM can intelligently discard irrelevant benign interactions (preventing explosion) while preserving the latent memory of genuine malicious influence deep within its hidden state, effectively modeling optimal tag decay purely from data distributions without requiring manual heuristics.

### **Expansion into Decentralized Information Flow Control**

Beyond localized intrusion detection, this architecture has profound implications for generalized Decentralized Information Flow Control (DIFC) in enterprise environments. In complex microservice architectures and autonomous event-driven AI ecosystems, explicitly tracking the provenance of data as it transforms across APIs is exceedingly difficult and currently relies on strict, easily bypassed schema validations.31 A learnable state propagation model could be deployed to ingest distributed tracing logs, dynamically enforcing data privacy boundaries and identifying complex data leaks that evade deterministic access controls.

### **Securing the Neural Engine**

As this novel paradigm relies heavily on the internal mechanics of an SSM, engineers must prioritize the security of the model itself. The architecture must incorporate robust mitigations against state erasure, adversarial state saturation, and spectral input exploitation.25 Ensuring strict tokenization boundaries on audit log fields and monitoring the entropy of the SSM's hidden state will be paramount to prevent sophisticated adversaries from blinding the propagation engine.

### **Final Verdict on Novelty**

The initial hypothesis is thoroughly validated by the literature. While the foundational components—neural taint analysis (Neutaint, nnTaint), provenance graph IDSes (KAIROS, Flash), and SSM-based security sequence modeling (MeeDet, Sentient)—exist independently in the literature, their synthesis into a single framework where an SSM directly governs the dynamic, explicitly learnable propagation of state across a system graph is entirely absent from the current state-of-the-art.  
This confirms that the concept of learnable state propagation across entities via State Space Models is genuinely novel. It provides a clear, highly defensible path to claim a major architectural contribution, establishing a new paradigm that replaces brittle, deterministic security rules with continuous, mathematically derived neural flow dynamics.
